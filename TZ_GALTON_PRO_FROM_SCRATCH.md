## 1. Общее описание продукта

Приложение представляет собой фотореалистичный 3D-симулятор **доски Гальтона (квинкункса)** для демонстрации биномиального распределения, Центральной предельной теоремы (ЦПТ), треугольника Паскаля и влияния физических параметров (наклона доски, коэффициента упругости удара, дефектов решётки штырьков) на форму гауссовского колокола, дополненный **интерактивным лабораторным практикумом** для студентов.

### Ключевые возможности:
1. **3D-сцена на Three.js**:
   - Деревянно-латунный корпус доски под прозрачным стеклом на лабораторном столе.
   - Верхняя воронка с очередью шариков, треугольная решётка латунных штырьков (от 4 до 20 рядов), нижние накопительные ячейки (стаканчики) с перегородками.
   - Механический рычаг справа от корпуса для сброса шариков (открывает нижние люки, шарики высыпаются вниз) и 3D-пульт управления на столе с OLED-дисплеями статистики.
   - Четыре режима окружения («Лаборатория», «Студия», «Чертёж / Фронтально», «По слоям / Exploded View» с раскладкой компонентов на 4 демонстрационных подиума).
   - Наглядная аналогия «Толпа людей» (72 3D-фигурки людей, выстраивающихся в живую гистограмму по росту от 154 до 186 см позади стола).
2. **Двухрежимное физическое ядро (`GaltonSimulator`)**:
   - Поддержка до **4 000 шариков** одновременно при 60 FPS за счёт `THREE.InstancedMesh` и предвычисленных сплайнов траекторий.
   - **Режим 1 (`'bernoulli'`)**: Классическая схема независимых испытаний Бернулли с вероятностью поворота вправо $p \in [0.15, 0.85]$, зависящей от угла наклона доски.
   - **Режим 2 (`'physics'`)**: Квазифизическая модель упругого рассеяния с коэффициентом восстановления (упругости) $e \in [0.20, 0.90]$, учитывающая перенос горизонтального импульса между рядами и перескоки через ячейки при высоком $e$.
   - **Интерактивные дефекты доски**: Возможность кликом мыши (Raycasting) «вынуть» или вернуть любой штырёк; при попадании на пустое место шарик пролетает ряд вертикально вниз без отскока.
3. **Система 3D/2D-оверлеев**:
   - Неоновая кривая нормального распределения (колокол Гаусса) поверх ячеек.
   - Горизонтальные засечки точного биномиального распределения $N \cdot P(k)$ на каждом столбике.
   - Рёбра и биномиальные коэффициенты $C_n^k$ треугольника Паскаля прямо поверх штырьков.
   - Подсветка траектории случайного «избранного» шарика (Featured Bead).
   - Одновременное отображение эталонной кривой **Серии A** и текущей **Серии B** при сравнении двух экспериментов.
   - Плавающие информационные плашки (Pill Tags) с защитой от наложения.
4. **Процедурный звуковой движок (`SoundEngine`)**:
   - Синтез на чистом Web Audio API (без внешних аудиофайлов): стеклянно-металлический перезвон штырьков с панорамированием по координате $X$ и повышением тона по номеру ряда, щелчки кнопок, трещотка рычага и звук высыпания шариков.
5. **Лабораторный практикум (всплывающее окно / модальная панель)**:
   - Автоматический захват высот столбиков $h_i$ (в мм) напрямую из 3D-симулятора.
   - Сравнение серий A и B, расчёт начальных и центральных моментов ($\bar{x}, \overline{x^2}, \sigma$), тренажёр проверки студенческих расчётов, 10-кратный численный эксперимент по изучению статистических флуктуаций, экспорт отчёта в **SVG**, **CSV** и **LaTeX**.

## 4. Математическое ядро (`src/math-stats.js`)

Модуль чистых математических функций без зависимостей от DOM и Three.js:

1. **Интерполяции**:
   - `clamp(x, min, max)`
   - `lerp(a, b, t)`
   - `smoothstep(edge0, edge1, x)`
   - `easeOutCubic(t) = 1 - Math.pow(1 - t, 3)`
   - `easeInOutQuad(t)`
2. **Детерминированный ГПСЧ (PRNG)**:
   - `createPRNG(seed)` — алгоритм **Mulberry32**, возвращающий функцию `() => number` в диапазоне $[0, 1)$.
   - `hashUint32(x)` и `hash2D(a, b)` — быстрый детерминированный целочисленный хэш, возвращающий число в $[0, 1)$. Используется для того, чтобы траектория $i$-го шарика на $r$-м ряду была воспроизводимой, но уникальной.
3. **Треугольник Паскаля (`PASCAL`)**:
   - Предвычисленный двумерный массив биномиальных коэффициентов $C_n^k$ от $n = 0$ до $n = 22$:
     $$C_n^0 = C_n^n = 1, \quad C_n^k = C_{n-1}^{k-1} + C_{n-1}^k$$
4. **Связь наклона доски и вероятности `tiltToProb(tiltDeg)`**:
   - При наклоне доски на угол $\theta \in [-12^\circ, +12^\circ]$ вероятность отскока шарика вправо равна:
     $$p(\theta) = \text{clamp}(0.5 + 0.025 \cdot \theta,\; 0.15,\; 0.85)$$
5. **Биномиальное распределение `computeBinomPMF(n, p, outArray = new Float64Array(n + 1))`**:
   - Заполняет массив вероятностей для $k = 0 \dots n$:
     $$P(k) = C_n^k \cdot p^k \cdot (1 - p)^{n - k}$$
   - Обязательно предусмотри значение по умолчанию для `outArray`, чтобы вызов `computeBinomPMF(n, p)` с двумя аргументами возвращал новый массив и не выбрасывал `TypeError`.
6. **Гауссиана и метрика сходимости**:
   - `normalPDF(z) = Math.exp(-0.5 * z * z) / Math.sqrt(2 * Math.PI)`
   - `normalCDF(z)` — аппроксимация функции ошибок Абрамовица — Стегана (точность $1.5 \times 10^{-7}$).
   - `computeTotalVariation(counts, settledCount, targetPMF, n)`:
     $$\text{TV} = \frac{1}{2} \sum_{k=0}^{n} \left| \frac{\text{counts}[k]}{\text{settledCount}} - P(k) \right|$$
     Показывает суммарное отклонение эмпирической гистограммы от идеального теоретического распределения (при $N \to \infty$ стремится к 0 по закону больших чисел).

## 5. Физическое ядро и симулятор (`src/simulation.js`)

> **ВАЖНО:** Не импортируй `three` в `simulation.js`! Для временных координат используй простой объект `{ x: 0, y: 0, z: 0 }`, чтобы ядро можно было тестировать в Node.js.

### 5.1. Координатная сетка доски (`getGridMetrics(n)`)
Для заданного числа рядов $n \in [4, 20]$:
- Число накопительных ячеек (стаканчиков): $n_{\text{bins}} = n + 1$ (индексы $k = 0, 1, \dots, n$).
- Горизонтальный шаг между центрами соседних штырьков в ряду (и шаг ячеек):
  $$d = \frac{\text{BOARD\_SPAN\_X}}{n + 1}$$
- Вертикальный шаг между рядами штырьков:
  $$\text{rowDy} = \frac{\text{PEG\_SPAN\_Y}}{\max(n - 1, 1)}$$
- Масштаб размера шариков/штырьков относительно эталона $n = 12$:
  $$s = \text{clamp}\left(\frac{13}{n + 1},\; 0.65,\; 1.60\right)$$
- Число шариков, помещающихся в один горизонтальный ряд внутри одной ячейки (с учётом 4 слоёв глубины `Z_LAYERS`):
  $$W = d - 0.018 \cdot s, \quad \text{cols} = \max\left(1,\; \left\lfloor \frac{W}{\text{BEAD\_DIAM} \cdot s} \right\rfloor\right), \quad \text{perLayer} = 4 \cdot \text{cols}$$
- Координаты штырька в ряду $r \in [0, n-1]$ и колонке $c \in [0, r]$:
  $$\text{pegX}(g, r, c) = \left(c - \frac{r}{2}\right) \cdot g.d, \qquad \text{pegY}(g, r) = \text{PEG\_TOP\_Y} - r \cdot g.\text{rowDy}$$
- Координата центра ячейки $k \in [0, n]$:
  $$\text{binX}(g, k) = \left(k - \frac{n}{2}\right) \cdot g.d$$
- Высота столбика в ячейке при наличии в ней `count` шариков:
  $$\text{binHeightY}(g, \text{count}) = \text{BIN\_BOTTOM\_Y} + g.\text{beadR} + \frac{\text{count}}{g.\text{perLayer}} \cdot g.\text{layerH}$$

### 5.2. Класс `GaltonSimulator`

#### Поля экземпляра:
- `n` (число рядов, по умолчанию 14), `p` (вероятность вправо, 0.5), `restitution` (коэффициент упругости $e$, по умолчанию 0.55), `simMode` (`'bernoulli'` или `'physics'`), `rate` (скорость выпуска шариков в секунду), `target` (целевое число шариков в пуле).
- `disabledPegs = new Set()` — множество выключенных штырьков, ключи формата `"${r}_${c}"`.
- Типизированные массивы на `MAX_BEADS = 4000` элементов:
  - `spawnAt` (`Float32Array`) — время выхода шарика из воронки;
  - `hit0At` (`Float32Array`) — время удара о первый штырёк $(0, 0)$;
  - `settleAt` (`Float32Array`) — время полного оседания на дно ячейки;
  - `rowDur` (`Float32Array`) — длительность пролёта одного межрядья ($\approx 0.068\text{ с}$);
  - `pathBits` (`Uint32Array`) — битовая маска поворотов;
  - `waypointX` (`Float32Array` размера `MAX_BEADS * (MAX_ROWS + 1)`) — точные горизонтальные координаты шарика на каждом ряду $r = 0 \dots n$;
  - `archScale` (`Float32Array` размера `MAX_BEADS * MAX_ROWS`) — коэффициент высоты параболической дуги отскока на каждом ряду;
  - `binIdxArr` (`Uint8Array`) — индекс итоговой ячейки $k \in [0, n]$;
  - `slotPos` (`Float32Array` размера `MAX_BEADS * 3`) — финальная 3D-позиция $(x, y, z)$ шарика в ячейке;
  - `lastSoundRow` (`Int8Array`) — последний озвученный ряд для каждого шарика (чтобы звук удара проигрывался ровно 1 раз на ряд).

#### КРИТИЧЕСКОЕ ПРАВИЛО расчёта траектории в `_initBead(i, spawnTime)`:
> **Внимание! Типичная ошибка LLM:** Нельзя изменять индекс колонки `col` ДО записи координаты на ряду $r = 0$! На ряду $r = 0$ существует только один центральный штырёк $(0, 0)$ с координатой $X = 0$.

Правильный алгоритм цикла по рядам $r = 0 \dots n-1$:
```javascript
let col = 0;       // На входе в ряд r = 0 шарик ВСЕГДА над центральным штырьком (0, 0)
let vx = 0;        // Горизонтальная скорость (для режима 'physics')
const base = i * (MAX_ROWS + 1);

for (let r = 0; r < n; r++) {
  // 1. СНАЧАЛА записываем координату текущего штырька (r, col), на который падает шарик:
  this.waypointX[base + r] = pegX(g, r, col);

  // 2. Проверяем, не вынут ли штырёк пользователем:
  const isPegDisabled = this.disabledPegs.has(`${r}_${col}`);

  if (isPegDisabled) {
    // Штырька нет — шарик проваливается вертикально вниз без дуги отскока!
    this.archScale[i * MAX_ROWS + r] = 0.0;
    // При свободном падении на ряд r+1 физическая координата X сохраняется,
    // что в треугольной сетке соответствует сдвигу индекса col на +0.5 (округляем детерминированно):
    const nextColFloat = col + 0.5 + vx * 0.35;
    col = clamp(Math.round(nextColFloat + (hash2D(i + 17, r) - 0.5) * 0.2), 0, r + 1);
  } else if (this.simMode === 'physics') {
    // Квазифизический режим с коэффициентом восстановления e = this.restitution (0.20 .. 0.90)
    const e = this.restitution;
    this.archScale[i * MAX_ROWS + r] = 0.5 + e * 0.85;

    // Случайный микро-импульс при ударе о цилиндрический штырёк + смещение от наклона доски
    const rnd = hash2D(i + 1, r * 31 + this._seed);
    const bias = (this.p - 0.5) * 2.0; // от -0.7 до +0.7
    const kick = (rnd < this.p ? 0.5 : -0.5) + (hash2D(i + 99, r) - 0.5) * (e - 0.35) * 1.4;

    // Перенос горизонтального импульса с затуханием (при малом e гасится, при большом e раскачивается)
    vx = vx * (e * 0.85) + kick * (0.65 + e * 0.7) + bias * 0.25;

    const deltaCol = Math.round(0.5 + vx);
    col = clamp(col + deltaCol, 0, r + 1);
  } else {
    // Классический режим Бернулли ('bernoulli')
    this.archScale[i * MAX_ROWS + r] = 1.0;
    const rnd = hash2D(i + 1, r * 37 + this._seed);
    const step = rnd < this.p ? 1 : 0;
    if (step) bits |= (1 << r);
    col += step;
  }
}

// 3. После прохождения последнего ряда (r = n - 1) записываем финальную координату входа в ячейку col:
const finalBin = clamp(col, 0, n);
this.waypointX[base + n] = binX(g, finalBin);
this.binIdxArr[i] = finalBin;
```

#### Интерполяция позиции шарика `sampleBeadPos(i, t, ax, ay, outVec)`:
По текущему времени симуляции `t` возвращает положение $i$-го шарика в `outVec`:
1. **Очередь в воронке (`t < spawnAt[i]`)**: шарик плавно движется по спирали/очереди внутри воронки к горловине `(0, FUNNEL_OUT_Y, 0)`.
2. **Падение из воронки на первый штырёк (`spawnAt[i] <= t < hit0At[i]`)**: вертикальное ускоренное падение от `FUNNEL_OUT_Y` до `PEG_TOP_Y`.
3. **Каскад по рядам штырьков (`hit0At[i] <= t < pegEndTime`)**:
   - Номер текущего ряда $r = \lfloor (t - \text{hit0At}[i]) / \text{rowDur}[i] \rfloor$, локальная фаза $u \in [0, 1)$.
   - Горизонтальная координата $X$ плавно интерполируется между `waypointX[base + r]` и `waypointX[base + r + 1]` через `smoothstep(0, 1, u)`.
   - Вертикальная координата $Y$ складывается из линейного спуска между `pegY(g, r)` и `pegY(g, r + 1)` плюс параболическая дуга подскока вверх:
     $$\Delta Y_{\text{arch}}(u) = 4 u (1 - u) \cdot (0.22 \cdot g.\text{rowDy}) \cdot \text{archScale}[i \cdot \text{MAX\_ROWS} + r]$$
4. **Падение в ячейку и укладка в слот (`pegEndTime <= t < settleAt[i]`)**:
   - Плавный переход от точки выхода из последнего ряда к персональному месту шарика в стаканчике `slotPos[i]` с небольшим затухающим отскоком при приземлении.
5. **Осевший шарик (`t >= settleAt[i]`)**:
   - Возвращает `slotPos[i]`. Если активен сброс шариков рычагом (`flushing === true`), добавляет свободное падение вниз сквозь открытое дно.

#### Статистика (`recomputeStats()`):
> **КРИТИЧЕСКОЕ ПРАВИЛО:** Различай массив `this.binN[k]` (сколько всего шариков при генерации было распределено в ячейку $k$ для расчёта высоты слотов) и `this.stats.count[k]` (сколько шариков **уже реально упало на дно** к текущему моменту времени `this.T >= this.settleAt[i]`)!
- Вся статистика на экранах, кривая Гаусса и метод `getHeightsMm()` для лабораторной работы должны опираться **только на `this.stats.count[k]`** (реально осевшие шарики)!
- Метод `getHeightsMm()` переводит количество осевших шариков `this.stats.count[k]` в высоту столбика в миллиметрах (1 осевший шарик в стандартном масштабе соответствует $0.16\text{ мм}$ высоты столбика, с округлением до $0.5\text{ мм}$).

## 6. Процедурный звук (`src/audio.js`)

Класс `SoundEngine` на базе Web Audio API:

> **КРИТИЧЕСКОЕ ПРАВИЛО БЕЗОПАСНОСТИ БРАУЗЕРА (Autoplay Policy):**
> Браузеры Chrome/Edge блокируют создание и запуск `AudioContext` до первого физического действия пользователя (`pointerdown`, `keydown`, `touchstart`, `mousedown`) и спамят в консоль ошибками `The AudioContext was not allowed to start`.
> Поэтому:
> 1. В конструкторе `SoundEngine` заведи флаг `this.unlocked = false` и повесь одноразовые слушатели (`{ once: true, passive: true }`) на `window` для событий `['pointerdown', 'keydown', 'touchstart', 'mousedown']`, которые вызывают `this.unlock()`.
> 2. В приватном методе `_ensureContext()` первой строкой проверяй:
>    `if (!this.enabled || !this.unlocked) return false;`
>    Пока пользователь ни разу не кликнул по странице, `new AudioContext()` даже не создаётся, и в консоли 0 предупреждений!

### Методы `SoundEngine`:
- `playPegHit(row, col, totalRows, velocity = 1.0)`:
  - Встроенный ограничитель частоты (rate-limiter): не чаще 28 звуков в секунду (`minPingInterval = 1 / 28`), чтобы при падении 2 000 шариков звук не превращался в гул.
  - Создаёт `OscillatorNode` (`sine` + короткий обертон `triangle`), частота которого растёт с номером ряда $r$:
    $$f = 520 \cdot 2^{\frac{r}{14}} + \text{jitter}\;\text{Гц}$$
  - Панорамирование (`StereoPannerNode`): $\text{pan} = \text{clamp}\left(\frac{col - r/2}{totalRows/2},\; -0.85,\; 0.85\right)$ — удары слева звучат в левом наушнике, справа — в правом.
  - Огибающая громкости (`GainNode`): быстрая атака ($2\text{ мс}$) и экспоненциальное затухание ($45\text{ мс}$) через общий `DynamicsCompressorNode`.
- `playClick(pitch = 1.0)` — короткий механический щелчок для кнопок и тумблеров.
- `playLeverPull()` и `playFlushWhoosh()` — звук натяжения пружины рычага и шорох высыпающихся шариков.

3. **Планарные отражения пола (`renderPlanarReflection`)**:
   - Отражающая камера `reflectCamera` зеркалирует основную камеру относительно плоскости стола $Y = \text{reflectionPlaneY}$.
   - **КРИТИЧЕСКОЕ ПРАВИЛО (Косая плоскость отсечения / Oblique Near-Plane Clipping):**
     Объект `THREE.Plane` **НЕ ИМЕЕТ** метода `.multiplyScalar()`! Для модификации матрицы проекции камеры отражения переводи плоскость в 4D-вектор `clipVector = new THREE.Vector4()`:
     ```javascript
     clipPlane.setFromNormalAndCoplanarPoint(planeNormal, planePoint).applyMatrix4(reflectCamera.matrixWorldInverse);
     clipVector.set(clipPlane.normal.x, clipPlane.normal.y, clipPlane.normal.z, clipPlane.constant);

     const projElements = reflectCamera.projectionMatrix.elements;
     qVector.set(
       (Math.sign(clipVector.x) + projElements[8]) / projElements[0],
       (Math.sign(clipVector.y) + projElements[9]) / projElements[5],
       -1.0,
       (1.0 + projElements[10]) / projElements[14]
     );

     const dotVal = clipVector.dot(qVector);
     if (Math.abs(dotVal) > 1e-6) {
       clipVector.multiplyScalar(2.0 / dotVal);
       projElements[2] = clipVector.x;
       projElements[6] = clipVector.y;
       projElements[10] = clipVector.z + 1.0;
       projElements[14] = clipVector.w;
     }
     ```
4. **Цепочка постобработки (`EffectComposer`)**:
   - Рендер основной сцены с записью буфера глубины `tSceneDepth`.
   - `GTAOPass` (экранное затенение углов и стыков).
   - Опциональный `BokehDofPass` (глубина резкости; убедись, что в `uniforms` присутствуют как `focus`/`range`, так и ссылки-алиасы `focusDist`/`focusRange`).
   - `UnrealBloomPass` (мягкое свечение неоновых графиков и золотых шариков).

## 10. Лабораторный практикум (`src/lab-module.js`)

> **ПРАВИЛО ИЗОЛЯЦИИ ИМЁН:** Назови внутренний объект состояния этого модуля `labState` (а НЕ `state`), чтобы при сборке в один файл (`standalone.html`) не возникло конфликта `Identifier 'state' has already been declared` с переменной `state` из `main.js`.

Модуль создаёт интерактивное окно лабораторной работы **«Изучение статистических распределений на доске Гальтона»** (открывается кнопкой `📋 Лабораторная` в нижней панели или клавишей `L`):

### Структура лабораторной работы:
1. **Панель синхронизации с 3D-доской**:
   - Кнопка **«📥 Снять замеры с 3D-доски»**: вызывает `window.__lab.getHeightsMm()`, считывает высоты столбиков $h_1 \dots h_{15}$ из 3D-симулятора, заполняет Таблицу 1 и перестраивает графики.
   - Кнопка **«📌 Зафиксировать как Серию А (эталон)»**: сохраняет текущее распределение в `window.__labSeriesA`, включает бирюзовую кривую на 3D-доске и на 2D-графике для A/B-сравнения двух опытов (например, без наклона и с наклоном, или при разных коэффициентах упругости $e$).
   - Кнопка **«🎲 Демо-данные»**: подставляет реалистичные экспериментальные замеры `[1, 2, 5, 11, 22, 38, 54, 62, 53, 39, 21, 10, 4, 2, 1]` мм.
2. **Таблица 1 (Статистический ряд и расчёт моментов)**:
   - 15 ячеек с номерами $x_i = 1, 2, \dots, 15$.
   - Строки таблицы (редактируемые поля ввода + авторасчёт):
     - $x_i$ — номер ячейки ($1 \dots 15$);
     - $h_i$ (мм) — экспериментальная высота столбика в $i$-й ячейке;
     - $w_i = \frac{h_i}{H}$ — относительная частота (доля шариков), где $H = \sum_{i=1}^{15} h_i$;
     - $x_i^2$ — квадрат номера ячейки;
     - $h_i x_i$ — произведение для расчёта первого начального момента;
     - $h_i x_i^2$ — произведение для расчёта второго начального момента;
     - $h_i^{\text{теор}}$ — теоретическая высота по формуле Гаусса:
       $$h_i^{\text{теор}} = \frac{H}{\sigma \sqrt{2\pi}} \exp\left(-\frac{(x_i - \bar{x})^2}{2\sigma^2}\right)$$
3. **Блок самопроверки студента**:
   - Поля для самостоятельного ввода студентом рассчитанных величин:
     $$\bar{x} = \frac{\sum h_i x_i}{H}, \qquad \overline{x^2} = \frac{\sum h_i x_i^2}{H}, \qquad \sigma = \sqrt{\overline{x^2} - (\bar{x})^2}$$
   - Кнопка **«✔ Проверить расчёты»**: сверяет ответы студента с точными значениями (допуск $\pm 2\%$) и подсвечивает поля зелёным/красным с подсказками.
4. **Интерактивный 2D-график (Canvas + векторный SVG)**:
   - Столбчатая гистограмма экспериментальных высот $h_i$, плавная огибающая кривая Гаусса $h(x)$, вертикальная линия математического ожидания $\bar{x}$, заштрихованный коридор $[\bar{x} - \sigma, \bar{x} + \sigma]$, полуширина на полувысоте $\text{FWHM} = 2\sqrt{2\ln 2}\,\sigma \approx 2.355\,\sigma$, а при наличии Серии А — наложение двух графиков и таблица дельт ($\Delta \bar{x}, \Delta \sigma$, двухвыборочный $t$-критерий).
5. **Численный эксперимент по изучению флуктуаций (Таблица 2)**:
   - Кнопка **«▶ Запустить 10 серий»**: проводит 10 независимых симуляций и заполняет таблицу 10 строк + столбец средних $\langle h_i \rangle$, наглядно демонстрируя, как относительная флуктуация $\delta \propto 1/\sqrt{N}$ уменьшается при усреднении по ансамблю.
6. **Экспорт результатов**:
   - **«⬇ Скачать график SVG»** — генерация чистого векторного файла `.svg` для вставки в курсовую/отчёт.
   - **«⬇ Скачать CSV (Excel)»** — таблица с UTF-8 BOM.
   - **«📄 Скачать LaTeX (.tex)»** — готовый компилируемый шаблон отчёта на русском языке с пакетом `booktabs` и заполненными таблицами.
   - **«🖨 Печать / PDF»** — открытие аккуратной печатной ведомости с выводами.

- **Плавный сброс без пересоздания WebGL-сцены**: при смене числа рядов или нажатии «Сбросить» НЕ удаляй всю сцену и НЕ пересоздавай `WebGLRenderer` (это вызывает моргание экрана и сброс ракурса камеры). ## 13. Чек-лист самопроверки перед сдачей кода (Обязательно для LLM!)

Перед завершением работы проверь свой код по этим 7 пунктам:
1. [ ] **Проверка синтаксиса**: Выполни `node --check` для каждого `.js` файла — не должно быть ни одной синтаксической ошибки.
2. [ ] **Проверка импортов**: Убедись, что в `overlay-3d.js` импортирована константа `CASE_DIM` из `./config.js`, а между `main.js` и `lab-module.js` нет дублирования глобальной переменной `state`.
3. [ ] **Проверка ряда $r = 0$**: В `simulation.js` координата `waypointX[base + r]` записывается **ДО** прибавления шага `col += step`.
4. [ ] **Проверка высот гистограммы**: Кривая Гаусса и лабораторная работа используют `sim.stats.count[k]` (осевшие шарики), а не `sim.binN[k]`.
5. [ ] **Проверка `AudioContext`**: Звуковой контекст не создаётся до первого клика/клавиши пользователя (`this.unlocked === true`).
6. [ ] **Проверка `THREE.Plane`**: В `postfx.js` метод `.multiplyScalar()` вызывается у `clipVector` (`THREE.Vector4`), а не у `clipPlane` (`THREE.Plane`), и используется `THREE.PCFShadowMap`.
7. [ ] **Проверка математики практикума**: Сумма вероятностей $\sum_{k=0}^{n} P(k) = 1.000000$, при $e = 0.25$ колокол узкий ($\sigma \approx 1.3$), при $e = 0.85$ — широкий ($\sigma \approx 3.2$), а экспорт в SVG, CSV и LaTeX отдаёт корректные файлы.
